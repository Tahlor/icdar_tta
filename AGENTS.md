# Agent steering

This repository is a shared planning/analysis workspace for the ICDAR 2026 TTA talk and follow-up replication work.

## Roles

### Cloud development agent

The cloud agent owns repository structure, experiment design, analysis contracts, issue decomposition, review of incoming evidence, and final integration on `master`.

- Treat current `master`, issue comments, and newly committed local-agent evidence as authoritative.
- Prefer small, reproducible changes that leave a clear audit trail.
- Verify every write remotely after committing.
- Do not claim a test or result passed unless the underlying artifact/result is available.

### Local data/compute agent

The local agent is the hands-on data and runtime agent. Its first responsibility is to discover the actual existing paper data and code before re-running expensive inference.

The local agent should:

1. Pull the exact `master` SHA specified in its task.
2. Locate the source images, labels, original augmentation images/configurations, model response files, paper-era analysis code, CV fold definitions, prompts, and any billing/token logs.
3. Record paths and provenance according to `docs/DATA_CONTRACT.md`.
4. Reuse existing responses whenever possible; do not silently regenerate historical outputs.
5. Commit portable metadata, scripts, manifests, derived tables, logs, and checksums. Do not commit secrets or private archival data.
6. Report exact commands, timestamps, model IDs, row counts, failures, and output paths in the relevant issue.

## Source-of-truth priority

When sources disagree, use this order:

1. Raw images/labels and raw model responses.
2. Versioned scripts/configuration used to generate derived outputs.
3. Recomputed normalized metrics.
4. Paper tables/text.
5. Presentation notes.

Paper numbers are regression targets, not ground truth if raw evidence shows otherwise.

## Data policy

- Raw/private archival images should remain outside Git unless their release status is explicitly known to permit repository inclusion.
- Machine-specific paths belong in an ignored local manifest. Commit a portable/redacted manifest containing dataset identity, counts, checksums, relative layout, and storage notes.
- Preserve raw model outputs byte-for-byte when feasible. Derived data should point back to raw response identifiers.
- Every new inference run must record model/provider identifier, execution date, prompt hash, image/transform ID, generation parameters exposed by the API, usage/token counts when available, latency, status, and cost/pricing provenance.

## Experimental integrity

- Reproduce the paper-era baseline before changing algorithms.
- Do not tune modern-model transforms on the test labels in the initial replication.
- First-pass modern-model experiments should reuse fixed perturbation configurations chosen from the historical workflow; this tests transfer rather than per-model retuning.
- Do not selectively omit models or perturbations because their results weaken the story. Main-deck selection may be editorial, but the full tested-model summary must remain available in the repository/backup material.
- Clearly distinguish repeated unchanged-image sampling, temperature/sampling controls, visual perturbations, and mixed ensembles.
- The historical work did **not** systematically search compound transforms within one image. Do not describe it as though it did. `blur + resize` and standard resize preprocessing are specific exceptions.

## Analysis objective

The primary deployment-oriented objective is not maximum aggregate field accuracy. It is:

> Minimize manual review subject to an explicit accepted-field quality/precision target and a known inference budget.

Still report conventional CER and exact field accuracy for comparability.

## Figure policy

- Main-deck figures should be newly generated for the presentation.
- Every figure must be generated by code from a machine-readable table.
- Store derived chart tables separately from rendered SVG/PDF/PNG.
- Avoid hand-edited numerical labels that can drift from source data.
- Charts should have a one-sentence intended takeaway in `docs/CHART_PLAN.md`.
- Chart generation must work locally and, once scripts stabilize, in a generic/cloud Python environment without access to the original image corpus whenever the required derived tables are committed.

## Branch/workflow policy

Unless the user explicitly requests otherwise, integrate accepted changes on `master`. Temporary branches are allowed only when a connector/write workflow requires them; verify the merged `master` SHA and delete temporary branches afterward.
