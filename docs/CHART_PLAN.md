# New chart plan

The presentation should use new charts derived from the underlying field-level outputs rather than copying the paper's result tables. Each chart below has a specific argumentative job.

## Priority A — main-deck charts

### C1. Useful diversity: individual error vs error correlation

**Question:** Why do visual perturbations help more than merely asking the autoregressive model again?

**Proposed design**

- Scatterplot.
- x-axis: mean pairwise field-error correlation within the strategy (lower is more diverse).
- y-axis: mean individual CER or field-error rate (lower is more accurate).
- Point labels for transformation family/control.
- Emphasize a small set in annotations: repeated unchanged image / low-temperature historical control, resize, pad, grid warp, high-temperature historical control.
- Optional secondary annotation: 10-sample consensus CER or consensus gain.

**Takeaway:** useful ensembles need members that are individually informative **and** make different mistakes. Sampling randomness can lower correlation while simultaneously degrading the members; visual perturbations can produce a better tradeoff.

**Temperature treatment:** temperature is a negative/control result, not a section of the talk. It earns a point/annotation on this chart because it helps distinguish generic autoregressive randomness from visually induced diversity.

**Required derived table:** `outputs/derived/strategy_summary.csv`

Suggested columns: `model_id,strategy,n_samples,individual_cer,individual_field_accuracy,error_correlation,consensus_cer,consensus_field_accuracy`.

### C2. Effective sample size vs error correlation

**Question:** Why can ten calls behave like barely more than one independent opinion?

**Proposed design**

- One theoretical curve for `N=10`:

  `N_eff = N / (1 + (N - 1) rho)`

- x-axis: pairwise error correlation `rho`.
- y-axis: stylized effective sample size.
- Annotate empirical correlation values for selected historical strategies (especially Resize, Pad, Grid Warp).
- Clearly label the curve as **stylized theoretical intuition** rather than a measured effective sample count.

**Takeaway:** adding correlated samples has rapidly diminishing informational value.

**Required derived table:** `outputs/derived/error_correlation_summary.csv`; theoretical points can be generated by the chart script.

---

### C3. Precision vs automatic coverage

**Question:** If we auto-accept fields based on ensemble agreement, how much human review can we safely avoid?

**Proposed design**

- x-axis: automatic coverage = fraction of fields accepted without review.
- y-axis: precision/accuracy among accepted fields.
- Sweep confidence/agreement thresholds.
- Main lines: Pad, Grid Warp, and a practical mixed ensemble if supported.
- Optional faint control: repeated unchanged-image sampling.
- Add horizontal guide(s) at a presentation target such as 99% / 99.5% only after deciding which targets are statistically defensible for this dataset.
- Where sample size permits, add uncertainty intervals or explicitly report accepted-field counts near the highlighted operating points.

**Takeaway:** grid warp may be more valuable as a **selective confidence generator** than as the most accurate individual transform.

**Important:** do not call a raw agreement score a calibrated probability unless calibration has actually been applied and evaluated.

**Required derived table:** `outputs/derived/precision_coverage.csv`

Suggested columns: `model_id,strategy,n_samples,confidence_threshold,accepted_fields,coverage,accepted_correct,precision,review_fields` plus uncertainty bounds when computed.

---

### C4. Inference cost vs manual review frontier

**Question:** What are we actually optimizing in production?

**Proposed design**

- x-axis: inference cost normalized to a stable unit (prefer dollars per 1,000 extracted fields or per 1,000 source documents; decide after inspecting usage logs).
- y-axis: fields requiring human review per 1,000 fields at a fixed accepted-field precision target.
- Each point: strategy + sample count, e.g. 1, 2, 3, 5, 10 samples; include adaptive early-stop points if implemented.
- Optionally include different current models when costs are measured under the same accounting method.
- Annotate **incremental inference cost per manual review avoided** for one or two useful transitions.

**Takeaway:** the objective is not maximum benchmark accuracy; it is fewer human reviews for a known quality and inference budget.

**Do not** hard-code today's public list prices into the chart source. Store pricing snapshots/provenance separately and prefer provider-reported usage from the actual runs.

**Required derived tables:** `outputs/derived/cost_by_run.csv` and `outputs/derived/review_frontier.csv`.

### C5. Shift periodicity simplified

**Question:** Why can padding/pixel shifting change the transcription if the text itself is unchanged?

**Proposed design**

- Main figure: agreement with baseline transcription vs horizontal (or combined directional) pixel displacement for the fine-grained shift sweep.
- Mark/reveal 16-pixel intervals after the curve is visible.
- Keep FFT and coarse shift analysis in backup unless the simplified plot cannot support the claim.

**Takeaway:** the model's transcription exhibits periodic sensitivity to image alignment, consistent with patch/grid processing artifacts.

**Wording caution:** do not claim the experiment proves a proprietary model's exact internal architecture.

**Required derived table:** `outputs/derived/shift_agreement.csv`

## Priority C — backup/supporting analyses

### C7. Which augmentations actually contribute to the ensemble?

Do not reproduce a giant ranking table. Prefer one compact measure such as:

- selection frequency across CV folds/sample counts;
- leave-one-family-out change in consensus CER/coverage;
- marginal contribution when greedily adding a family on validation data.

This chart exists to support one sentence, not a major section.

### C8. Ensemble size / diminishing returns

Plot coverage-at-fixed-precision and/or consensus CER against sample count for the key strategies. This is especially useful if adaptive stopping is added.

### C9. Failure examples

Small qualitative panel showing rare high-agreement wrong cases: ambiguous characters, normalization/autocorrection-like changes to unusual names, struck-through/interlineated text.

## Chart acceptance checklist

A figure is ready for the deck only if:

- its input table can be regenerated by code;
- the script and source table are versioned;
- the title/takeaway does not overclaim causality or calibration;
- sample counts are visible or available in notes;
- all metrics use one documented field-filtering/normalization policy;
- any confidence interval method is recorded;
- measured vs theoretical/estimated quantities are visually and textually distinguishable;
- the figure renders from a generic Python environment without access to raw images unless images are inherently part of the figure.
